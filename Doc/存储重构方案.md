# 存储重构方案

## 目标

- 新数据统一写入 Electron `userData/app-data/*.json` 文件，降低 `localStorage` 容量和损坏风险。
- 旧 `localStorage` 数据继续保留，作为回滚和旧版本兼容备份。
- 首次启动新版时自动生成完整 `localStorage` 快照，防止迁移过程中误覆盖。
- 迁移采用渐进方式：大数据模块优先迁移，其他模块先做文件镜像。

## 存储层级

1. `localStorage`
   - 继续保留旧 key。
   - 作为兼容备份，不主动删除。

2. `userData/app-data`
   - 新的 JSON 主存储位置。
   - 通过 `saveAppData/loadAppData` 写入。
   - 统一数据使用 `__guyueUnifiedStorage` envelope 包装，保留来源、更新时间和旧 key 信息。

3. 用户真实文件路径
   - Git 仓库、音乐文件、数据中心文件管理、RAG 源文档仍然只记录路径或直接操作原文件。
   - 不复制、不托管，避免误删用户文件。

4. 托管资源目录
   - 工作空间、LaTeX、RAG 索引、插件、运行临时文件继续使用现有 `userData` 子目录。

## 迁移规则

- 启动时先创建 `storage-localStorage-snapshot-latest.json` 和带时间戳的快照。
- 读取数据时优先读 `app-data`。
- 如果 `app-data` 不存在，则从旧 `localStorage` 读取并写入 `app-data`。
- 保存数据时同时写：
  - 新 `app-data`
  - 旧 `localStorage` key
- 如果 `app-data` 和旧 `localStorage` 同时存在但内容不同，会额外保存旧数据副本，避免被覆盖后无法找回。

## 已接入模块

- 题库：题目、分类、解题方法、AI 配置、UI 状态。
- 画布：画布数据、当前画布、分类、素材库、LaTeX 映射、默认工具配置。
- App 基础数据：笔记、SSH、API、待办、文件、Prompt、Markdown、热力图等会同步镜像到 `app-data`。
- 循环事项、音乐曲目和歌单会同步镜像到 `app-data`。

## 后续迁移原则

- 大对象和长期内容应迁到 `app-data` 或专门目录。
- UI 状态、小型偏好可以继续镜像到 `localStorage`，但不能只存在于 `localStorage`。
- 删除旧 key 必须单独做版本迁移，并在用户确认后执行。
